# clue-extract mapping: MADR

Source mapping for [clue-extract](../skill.md) — the target contract in `skill.md` governs; this file only says what maps where for a MADR (or Nygard-style) decision corpus.

Layout: decision records live in `docs/decisions/` or `doc/adr/`, one file per record, most often a numeric filename prefix (`0005-use-postgres.md`, `05-use-postgres.md`). A MADR 3.x/4.x record carries frontmatter (`status`, `date`, `decision-makers`, `consulted`, `informed`) plus the template headings — Context and Problem Statement, Decision Drivers, Considered Options, Decision Outcome, Consequences, More Information. The same folders often mix in older, heading-only Nygard records with no frontmatter at all — just `# Title`, `## Status`, `## Context`, `## Decision`, `## Consequences`.

| MADR | Cliewen |
|---|---|
| `status: proposed` | a proposal is not a decision, and a converted record born `inferred` becomes binding on merge — so a `proposed` source record converts only when the repository has in fact been living by it, and the body says so in one sentence. A proposal never acted on converts to an open question in the extraction report and a named plan door for deciding it, not to a decision record; the extraction report states which way each `proposed` record went |
| `status: accepted` | born `inferred` regardless — MADR's `accepted` names a reviewer's own acceptance, not the Cliewen merge boundary the vocabulary's `verified` promotes on; `accepted-by: []` |
| `status: rejected` | kept `inferred`, never deleted — a Cliewen decision record is never removed once written, rejected or not, so a `rejected` source record converts to a kept record under that existing rule rather than a new one. What the record states is that the option was rejected and why: the rejection is the decision the record carries, stated in `## Decision outcome` or as its own `### Rejected: <option>` section, never left implicit — a converted record whose body reads as an adopted decision would assert the opposite of what happened |
| `status: deprecated` | kept `inferred`; a body-prose sentence states the record was deprecated and why, if the source says why |
| `status: superseded by NNNN-…` | kept `inferred`; body prose states the record was superseded, plus a `links:` edge to the converted successor's `ADR-xxx` ID once that record exists |
| `date` | body prose — a Cliewen decision record has no date field, so the source date is stated in the sentence that carries the record's history, alongside the acceptance names where the source has them and on its own where it does not; git history dates the conversion itself |
| `# Title` (or the `title` frontmatter key) | the `title:` frontmatter field, kept verbatim except for sentence-casing; the `# ADR-xxx — <title>` heading restates it |
| the rest of the source filename (`0005-use-postgres.md`) | the slug of the converted file name, `ADR-xxx-use-postgres.md` — the existing slug is kept verbatim, never re-worded, so the converted file is predictable from the source name alone |
| `decision-makers`, `consulted`, `informed` | body prose naming who accepted, who was consulted, who was informed, and the original date(s); the converted record's `accepted-by:` stays `[]` — the field records only approval given under this corpus's own merge boundary, never acceptance a source record already carried, so a real pre-existing acceptance is preserved as history rather than written into a field reserved for something else |
| numeric filename prefix (`0005-…md`, `05-…md`) | the number becomes the `ADR-xxx` ID — the numeric value is kept and never renumbered, written in the ID form the target corpus already uses for its own records, so the source's padding does not decide how the target corpus reads. A corpus already converted keeps the form it already carries: restyling its padded IDs to unpadded ones later is a renumbering, which this row forbids. Every preserved number is placed before any ID is minted, so the two passes below can never hand the same ID to two records |
| duplicate numbers across mixed folders (`doc/adr/0003-*` and `docs/decisions/0003-*` both exist) | the colliding records sort by full source path, and the first keeps the number (`doc/adr/0003-*` before `docs/decisions/0003-*`); every other record in the collision is minted a fresh ID in the pass below. Path order is used because it needs nothing beyond the file names, so the same corpus always resolves the collision the same way; state the old-number-to-new-ID mapping for every collided record in the extraction report |
| a preserved number the target corpus already uses (a repository already running Cliewen absorbs a leftover `doc/adr/` folder) | the existing `ADR-xxx` keeps its ID untouched — it is already a Cliewen record and renumbering it would break every reference to it — and the incoming record is minted a fresh ID by the row below, exactly as an unnumbered record is; state the old-number-to-new-ID mapping in the extraction report. Preservation reaches only numbers no record in the target corpus already holds |
| a record with no numeric prefix | minted the next free `ADR-xxx`, after every preserved number is placed — take the unnumbered records in the source's own stated or file order and assign upward from `max + 1` over all IDs already in the converted corpus, so a minted ID never collides with one kept verbatim. This is the same reproducible-minting shape the extraction contract states for criterion IDs, without borrowing its `ac-prefix:` namespace, since that item governs criteria and does not reach decision records |
| MADR template headings (Context and Problem Statement, Decision Drivers, Considered Options, Decision Outcome, Consequences, More Information) | Context and Problem Statement plus Decision Drivers fold into `## Context and problem statement`; Decision Outcome becomes `## Decision outcome`; each considered option that was not chosen becomes its own `### Rejected: <option>` section; Consequences and More Information fold into body prose or the `**Carrier:**` line, whichever the content actually is |
| older Nygard headings (`## Status`, `## Context`, `## Decision`, `## Consequences`) | `## Status` converts per the status-vocabulary rows above; `## Context` and `## Decision` become `## Context and problem statement` and `## Decision outcome`; `## Consequences` folds into body prose under Decision outcome or its own trailing sentence |
| Hand-maintained per-folder index (`INDEX.md`, `index.md`, a `## Contents` table) | absorbed into that folder's README `clue:index` rows, then deleted — the description, purpose, or scope column becomes the row's sentence, while a column that only restates a `links:` edge (a design or related-decision pointer) is dropped rather than carried |

Worked case: Robocode Tank Royale, a public repository extracted through `clue-extract` in 2026. Its decision corpus is what these rows are written against — 41 records in one `docs/decisions/` folder beside that folder's `README.md` and `log.md`, every record carrying a numeric filename prefix, five written to the MADR template headings and the rest to Nygard's `## Context` / `## Decision` / `## Consequences`. That conversion happened before this mapping existed, and it is where the `decision-makers` row above comes from: it wrote the records' own pre-Cliewen acceptance into `accepted-by:` (annotated `pre-Cliewen MADR acceptance`) and left them `status: verified`, so the corpus now shows approvals no human ever gave under its merge boundary. It also carried the source padding into the IDs themselves, which is the form that corpus now keeps — an already-converted corpus is never re-styled, per the numeric-prefix row above. The rows above are what that conversion would have followed.

Watch for: a folder mixing MADR and Nygard records side by side, where only some files carry frontmatter; a `superseded by` reference written three ways (a plain-prose mention in the Decision Outcome section, a `superseded-by:` frontmatter key, or an inline link to the successor file) that all mean the same `links:` edge; a record's number reused across `doc/adr/` and `docs/decisions/` from a past folder migration; a `proposed` record nobody ever acted on, which is an open question rather than a decision the merge would make binding; and the temptation to write `decision-makers` straight into `accepted-by:` because the names are already there — the shortcut looks harmless but a converted record's `accepted-by:` has to mean the same thing as every other record's.
