# Upgrade Cliewen and schedule Rumble announcement readiness

Plan-less: this change creates the next campaign rather than implementing an existing milestone. The maintainer requested the latest Cliewen release and a plan for the Rumble readiness audit's findings.

Upgrade the repository's managed instructions and CI caller to Cliewen 0.31.0, preserving its human-merged PR boundary. Record the audit, a public-participation goal, and a sequenced plan that starts with outside-contributor authentication and intake, then completes bot templates, participant instructions, cross-repository consistency and external onboarding verification. Creating the plan is tracked work; the mechanical upgrade is direct maintenance carried alongside it. No Rumble behavior or authentication architecture is chosen here.

The largest risk is assuming that maintainer-account success establishes public participation. The credible alternative is to keep Rumble an explicitly limited pilot until the public path is proven. The cheapest useful test is an outside-account submission through registration, intake, receipt and rankings. If that cannot meet the existing credential boundary, the first milestone must bring back a reviewed design decision before implementation. A campaign could complete every document and still fail Robocoders if nobody follows it without maintainer help; the final milestone therefore requires that journey and records every intervention.

The corpus has no vision document; this change proceeds under the existing learning-and-competition goal without inventing a new vision. The maintainer's explicit instruction authorizes this upgrade and plan preparation, not merging the PR or starting the planned implementation.
