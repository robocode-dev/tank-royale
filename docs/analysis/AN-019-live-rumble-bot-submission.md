# Live Rumble bot submissions

## Scope and result

This record supplies the live submission evidence that was still outstanding in [AN-018](AN-018-rumble-starter-validation.md). The starter templates and validator changes merged in [rumble-bots PR 11](https://github.com/robocode-dev/rumble-bots/pull/11), and the published author guide merged in [Tank Royale PR 286](https://github.com/robocode-dev/tank-royale/pull/286), before the live submissions. The owner `robocode-rumble-test` submitted the first `RumbleTestScout` bot in [rumble-bots PR 12](https://github.com/robocode-dev/rumble-bots/pull/12), then changed its source and submitted version 1.0.1 in [PR 14](https://github.com/robocode-dev/rumble-bots/pull/14). Both changes were merged and both versions appear in the generated bot index under the same owner.

The current [bots/index.json](https://github.com/robocode-dev/rumble-bots/blob/main/bots/index.json) has blob `54ac6af944d0078b7b6199316da068bc8d849c5b`, generated at `2026-10-19T19:39:23Z` from bot-repository commit `4a290569f87378b697234d452bd49c2a7a2aeefa`. It records `RumbleTestScout` 1.0.0 as `superseded` with source hash `sha256:c3e7eb79bd118346801b1a62fadd114b3c30dc470a17e78b5260779d59d3ce53`, and 1.0.1 as `active` with source hash `sha256:a989ca0d1a0d00bf335f956ece11374fdbc23fa6335e7165e70940c45e7a355e`; both entries identify owner `robocode-rumble-test` and platform `JVM`. The catalog was generated by the successful [manual publication run 39312774827](https://github.com/robocode-dev/rumble-bots/actions/runs/39312774827) after the version-update merge.

## Publication observations

The first submission's validation passed in [run 39308684022](https://github.com/robocode-dev/rumble-bots/actions/runs/39308684022). Its automatic publication run [39309054077](https://github.com/robocode-dev/rumble-bots/actions/runs/39309054077) failed when `github-actions[bot]` received HTTP 403 while pushing the generated catalog. [PR 13](https://github.com/robocode-dev/rumble-bots/pull/13) then fixed publication for merged fork submissions, and the documented manual recovery succeeded in [run 39310466773](https://github.com/robocode-dev/rumble-bots/actions/runs/39310466773). The required GitHub Actions permissions and recovery procedure are documented in [GOVERNANCE.md](https://github.com/robocode-dev/rumble-bots/blob/main/GOVERNANCE.md#github-actions-permissions).

The version-update validation passed in [run 39311998472](https://github.com/robocode-dev/rumble-bots/actions/runs/39311998472). After PR 14 merged, the push-triggered publisher [run 39312610451](https://github.com/robocode-dev/rumble-bots/actions/runs/39312610451) could not yet identify the merged bot PR through GitHub's commit-to-PR API. Manual recovery succeeded in [run 39312774827](https://github.com/robocode-dev/rumble-bots/actions/runs/39312774827), which produced the catalog snapshot above. [PR 16](https://github.com/robocode-dev/rumble-bots/pull/16) subsequently added a bounded retry for this association delay; its submission-validation workflow passed in [run 39312921808](https://github.com/robocode-dev/rumble-bots/actions/runs/39312921808). No later live submission has exercised the new automatic retry path, so that behavior remains unverified by a live publication.

[PR 15](https://github.com/robocode-dev/rumble-bots/pull/15) also updated validator test fixtures for multiple bot owners; its validation passed in [run 39311057577](https://github.com/robocode-dev/rumble-bots/actions/runs/39311057577), before the version-update validation. This isolated test correction supports the submission checks but is not itself evidence of the published catalog state.

## Evidence boundary

The index proves that both merged source versions were generated with the expected owner, status and distinct source hash. The linked validation and publication runs distinguish passing template/submission validation from automatic publication and manual recovery. The automatic retry introduced by PR 16 has not yet been observed on a later live bot merge. Four-language template smoke, dependency validation, JSON-only TwinDuel coverage and separate battles remain documented in [AN-018](AN-018-rumble-starter-validation.md); this record does not rewrite those historical results or claim additional server-connected behavior.
