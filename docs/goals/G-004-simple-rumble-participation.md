# Robocoders participate in Rumble without administering its infrastructure

**Who:** Bot developers entering the competition, volunteers contributing computer time, and the maintainer developing and testing Rumble.

**What:** Create and test bots, submit and update them, withdraw unwanted entries, inspect understandable rankings, and contribute battles with control over which bots receive their computing time. The maintainer can repeat and reset development tests without disturbing public participants.

**Why:** Repository manipulation, runtime setup, manual result posting, and repeated evidence collection discourage participation and make maintenance expensive. Competition should advance the existing learning-and-programming purpose while retaining moderation, auditable results, and contributor control.

The maintainer explicitly requested and confirmed this direction in the implementation-planning conversation: retain the current service as a public Beta, create a separate development test Rumble, use a dedicated Rumble GUI menu, and adopt local human acceptance. This verified goal does not claim that any of the requested features is implemented.
